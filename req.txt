## Prompt

I have a FastAPI service with a method `get_bau_details()` that returns BAU details for **Direct** and **Proxy** connections.

### Existing Behavior

* **Direct** BAU details are fetched from the local database using the `Connection` table.
* **Proxy** BAU details are fetched from:

  * Local database when running in PROD.
  * PROD API (`/team/bau-details`) when running in non-PROD environments.
* The response supports filtering, grouping by application, pagination, and returns team information.

### New Requirement

The DevOps team will **not populate the Connection table anymore** for BAU details.

Instead, I need to augment the existing response with BAU records coming from the **PROD environment**.

#### Requirements

1. Keep the existing Direct query exactly as it is.
2. All existing records coming from the `Connection` table should be marked as:

```python
user_declared = "N"
```

3. Call the PROD BAU Details API using the configured `prod_url`.

4. From the PROD response, consider only **active configurations** having a valid `batch.mon_eim_id`.

5. The value of `batch.mon_eim_id` may contain either:

   * EIM ID
   * Snow/Application ID

6. `business_app_id` is the Snow/Application ID.

7. Before adding a PROD record, check whether the application already exists in the Direct results.

8. If the record already exists in Direct results, ignore it.

9. If it does not exist, append it to the response and mark it as:

```python
user_declared = "Y"
```

10. The merged response should still support:

    * pagination
    * filtering
    * grouping
    * existing response schema

11. Do not duplicate records.

12. Use an efficient lookup (preferably a Python `set`) instead of nested loops.

13. Avoid rewriting the existing SQL queries unless absolutely necessary.

14. Refactor the code where appropriate so the method remains clean and maintainable.

### Expected Flow

```
Fetch Direct records
        │
        ├── Mark user_declared = "N"
        ├── Build a set of existing mon_eim_id/application IDs
        │
Fetch Proxy records
        │
Call PROD BAU API
        │
Filter only active configurations with valid mon_eim_id
        │
Skip records already present in Direct results
        │
Append remaining records
        │
Mark user_declared = "Y"
        │
Merge all records
        │
Paginate
        │
Return Response
```

### Goals

* Minimal changes to existing code.
* Preserve existing functionality.
* Efficient implementation (O(n) merge using a `set`).
* No duplicate BAU records.
* Clean, production-quality, maintainable code following existing coding style.
